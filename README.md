# Anthbot Genie → Sprut.Hub

Интеграция роботов-газонокосилок **Anthbot Genie** в умный дом **Sprut.Hub** — без Home Assistant,
без внешних мостов и сервисов: вся работа с облаком Anthbot идёт внутри сценария хаба.

Основано на реверсе облачного API из проекта
[vincentjanv/anthbot_genie_ha](https://github.com/vincentjanv/anthbot_genie_ha) (интеграция для Home Assistant).
Неофициальный любительский проект, с Anthbot никак не связан.

> **Перед заливкой в хаб уберите из сценариев комментарии.** Sprut.Hub молча не сохраняет
> крупные сценарии: исходник с документацией (≈64 КБ каждый) не доезжает — интерфейс не показывает
> ошибку, сценарий просто остаётся пустым. Комментарии здесь занимают больше половины объёма,
> и без них код укладывается в предел (≈39 и ≈36 КБ). Для этого есть сборщик:
>
> ```bash
> node tools/hubbuild.mjs
> ```
>
> Он вырезает комментарии по AST, а не регулярками: в коде есть регулярные литералы вида
> `/^https?:\/\//i`, на которых «убрать всё после `//`» ломает программу. Единственная
> зависимость — `acorn` (`npm i acorn`); он же подхватится сам из соседнего клона
> ScenarioSimulator, если вы уже склонировали его ради тестов.
>
> **Сохранение проверяйте, а не доверяйте иконке.** Хаб гасит значок «сохранить», даже когда
> сценарий не сохранился. Перезагрузите страницу редактора и сверьте число строк.
>
> **Если вставляете через буфер обмена — следите за кодировкой.** `pbcopy` без UTF-8 локали
> превращает кириллицу в мозаику, код при этом остаётся синтаксически верным и молча уезжает
> в хаб со сломанными строками статусов и сообщений. Сверяйте хеш файла и буфера.

## Как это работает

Локального протокола у косилки нет — приложение ходит в облако, поэтому и хаб ходит туда же:

1. логин на `api.anthbot.com` → bearer-токен;
2. список привязанных косилок, регион и AWS IoT endpoint устройства;
3. временные AWS-креды под конкретный серийник (`/iot/sts/arn`);
4. чтение состояния — `GET https://<endpoint>/things/<sn>/shadow?name=property` с подписью **AWS SigV4**;
5. команды — публикация в топик: `POST https://<endpoint>/topics/$aws/things/<sn>/shadow/name/service/update`
   с телом `{"state":{"desired":{"cmd":…,"data":…}}}`.

Именно публикация в топик, а не документированный `UpdateThingShadow`: на Genie 800 запись в
shadow облако принимает (HTTP 200), но косилка её не исполняет — прошивка слушает сам топик, а не
дельту shadow. Путь через `UpdateThingShadow` оставлен опцией сценария для других моделей.

В песочнице сценариев Sprut.Hub нет крипто-API и Java-классов, поэтому MD5, SHA-256 и HMAC-SHA256
реализованы на чистом ES5 внутри глобального сценария.

## Почему опрос, а не push

Состояние читается раз в минуту, и минутная задержка в карточке — единственная плата. Напрашивается
подписка на shadow-топики вместо опроса; она разобрана и **упирается не в облако, а в хаб**.

Со стороны AWS push открыт полностью — проверено на живом облаке
[пробой `wssprobe.mjs`](tools/wssprobe.mjs): рукопожатие принято, `CONNACK` = 0, `SUBACK` = QoS 1,
а после отправки `get_all_props` пришёл `PUBLISH` с состоянием. То есть временные креды из
`/iot/sts/arn` дают и `iot:Connect`, и `iot:Subscribe`, и подписка реально доставляет.

Упирается всё в песочницу сценариев Sprut.Hub: в ней есть HTTP, но нет ни WebSocket, ни сокетов,
а plain MQTT AWS IoT не принимает — только mTLS с клиентским сертификатом (он в прошивке косилки)
либо WSS с подписью SigV4. MQTT-контроллер хаба настраивается адресом и портом, а нужен `wss://`
с подписанной query-строкой, которую надо перевыпускать примерно раз в час. Значит push потребовал
бы постоянно работающего демона рядом с хабом — ровно того внешнего моста, от которого проект
уходил. Поэтому опрос.

> Если будете повторять пробу: подключаться идентификатором самой косилки нельзя — AWS IoT рвёт
> прежнее соединение с тем же `clientId`, и косилка потеряет связь с облаком. В пробе идентификатор
> заведомо свой, и в любом решении должно быть так же.

## Что подтверждено на живой косилке

Проверено на **Genie 800, прошивка 1.20.9**, регион `eu-central-1`. Критерий один: команда
считается рабочей, только если изменилось состояние, которое вернула **сама косилка**. Код 200
от облака ничего не значит — именно так обнаружилось, что часть команд уходит в никуда.

- **Все команды** — старт кошения всего газона, остановка, возврат на базу, кошение выбранных
  зон, кошение авто-зоны, высота, громкость, направление, датчик дождя, режим у базы. Полная
  таблица с именами команд — в [инструкции сценария](AnthbotGenie/README.md).
- **Чтение состояния и разметки участка** — включая формат Genie 800, который держит половину
  полей плоско и под другими именами, чем модели 600 / M5 / M9.
- **Подсветка зон**: кнопки зон показывают состав задания, которое косилка выполняет сейчас
  или выполняла последним, — в том числе запущенного из приложения Anthbot.

Чего косилка **не** отдаёт, сколько ни ищи: своей позиции на карте (поле `anti_loss_pose` —
опорная точка «антипотеряшки», а не координата робота), признака «идёт дождь», состава задания
по авто-зонам и наработки за всё время.

## Тесты

Тесты (180 штук) лежат в `AnthbotGenie/.tests/`. Раннер — `ScenarioSimulator` из репозитория
[Sprut.Hub_Tools](https://github.com/BOOMikru/Sprut.Hub_Tools); склонируйте его отдельно и
запустите, указав корень этого проекта:

```bash
bun run cli run AnthbotGenie --root /путь/к/anthbot_genie_sprut
```

## Безопасность

Логин и пароль Anthbot вводятся в опциях сценария в хабе и **никогда** не попадают в этот
репозиторий. Статические AWS-ключи, зашитые в референсной HA-интеграции, здесь не используются —
только временные креды из `/iot/sts/arn`, ограниченные одним серийником.
