# 🤖 Anthbot Genie — газонокосилка

Логический сценарий + глобальный сценарий-библиотека

> **Робот-газонокосилка Anthbot Genie в Sprut.Hub: состояние, запуск кошения, зоны и настройки**

У косилки нет локального протокола — мобильное приложение работает через облако производителя,
поэтому и хаб ходит туда же. Сценарий сам логинится в облако Anthbot, получает временные ключи
AWS, читает состояние косилки и отправляет ей команды. Ничего дополнительно разворачивать не нужно:
всё живёт внутри хаба.

---

## 💡 Что умеет

- показывает состояние: косит / на базе / возвращается / пауза, заряд батареи, признак зарядки;
- запускает и останавливает кошение, отправляет косилку на базу;
- запускает кошение выбранных зон — одной или сразу нескольких — и авто-зон;
- меняет высоту кошения, громкость подсказок, направление кошения;
- управляет датчиком дождя и паузой после дождя;
- управляет режимом кошения у базовой станции;
- показывает диагностику: ошибка, RTK, IP, Wi-Fi, площадь карты, наработка.

## ⚠️ Что нужно знать до установки

- **Управление идёт через облако Anthbot.** Нет интернета — нет управления. Задержка реакции равна
  периоду опроса (по умолчанию 60 секунд), после собственной команды состояние обновляется сразу.
- **Логин и пароль от аккаунта Anthbot** вводятся в опциях сценария и хранятся в настройках хаба
  открытым текстом. Это то же самое, что делают аналогичные интеграции для Home Assistant, но знать
  об этом стоит.
- **API производителя не документирован.** Он получен реверсом мобильного приложения (см.
  [anthbot_genie_ha](https://github.com/vincentjanv/anthbot_genie_ha)) и может измениться в любой момент.
- **Проверено на Genie 800** (прошивка 1.20.9, регион `eu-central-1`): чтение состояния, разметка
  участка и путь отправки команд подтверждены на живой косилке. Разбор состояния терпим и к формату
  моделей 600 / M5 / M9 — под них написана исходная HA-интеграция.

## 📦 Установка

> **Важно: что именно вставлять в хаб.** Хаб молча не сохраняет крупные сценарии — исходник
> с комментариями (61 КБ) не доезжает, и в редакторе остаётся пустой сценарий. Перед вставкой
> соберите версию без комментариев:
>
> ```bash
> node tools/hubbuild.mjs
> ```
>
> В `build/` появятся `AnthbotGenie.Global.hub.js` и `AnthbotGenie.Logic.hub.js` — вставлять в хаб
> нужно их. Логика от исходников не отличается, вырезаны только комментарии.

### 1. Глобальный сценарий

Создайте глобальный сценарий с именем `AnthbotGenie.Global` и вставьте в него содержимое
`build/AnthbotGenie.Global.hub.js` (исходник с комментариями —
[source/AnthbotGenie.Global.js](source/AnthbotGenie.Global.js)). В нём криптография, подпись
запросов к AWS и клиент облака — без него логический сценарий не заработает.

### 2. Виртуальный аксессуар

Логический сценарий не может создавать устройства, поэтому аксессуар создаётся руками:
**Настройки → добавить устройство → виртуальный аксессуар** (см.
[вики Sprut.Hub](https://wiki.spruthub.ru/Создание_виртуальных_аксессуаров)).

Сценарий находит нужные сервисы **по последнему слову в имени** — ключу из таблицы.
Начало названия пишите любое, ключ — точно как в таблице и обязательно последним словом.
Квадратные скобки вокруг ключа допустимы, но необязательны: хаб их из имени вырезает.
Сервисов, которых нет, сценарий просто не увидит — можно начать с основных и добавить остальные позже.

> **Порядок создания сервисов = порядок плиток.** Хаб выводит плитки в том порядке, в котором
> сервисы заведены в аксессуаре, и потом переставить их можно только вручную (шестерёнка →
> «Сортировка», перетаскиванием за `≡`). Поэтому **создавайте сервисы сразу в нужном порядке** —
> проще, чем перетаскивать два десятка строк потом. Рекомендуемая последовательность:
>
> 1. `mow`, `dock` — то, чем пользуются чаще всего
> 2. `battery`, `status`, `error` — состояние
> 3. `zone1…zoneN`, `azone1…azoneN` — зоны, их отмечают перед запуском кошения
> 4. `time`, `area` — наработка за сессию
> 5. `height`, `dir` — настройки, которые правят время от времени
> 6. `refresh`, `volume`, `dirauto`, `rain`, `raintime`, `nest`, `nestcount`, `nestheight`,
>    `nestcheck`, `nestlevel` — настройки «поставил и забыл»
> 7. `rtk`, `ip`, `ssid`, `fw`, `mapstate`, `maparea` — диагностика
>
> Сервисы из пунктов 6 и 7 сценарий **сам убирает с рабочего стола** при первом запуске (см.
> [Что видно на рабочем столе](#4-что-видно-на-рабочем-столе)), поэтому их позиция в списке
> роли не играет — важен порядок первых пяти пунктов.
>
> Тем же списком в одну строку, чтобы не собирать его заново при повторной установке:
> `mow`, `dock`, `battery`, `status`, `error`, `zone1…zoneN`, `azone1…azoneN`, `time`, `area`,
> `height`, `dir`, `refresh`, `volume`, `dirauto`, `rain`, `raintime`, `nest`, `nestcount`,
> `nestheight`, `nestcheck`, `nestlevel`, `rtk`, `ip`, `ssid`, `fw`, `mapstate`, `maparea`.
> Для семи зон и двух авто-зон это 34 сервиса, из них на рабочем столе остаются первые 18.

Каждый сервис заводится одинаково: **«Добавить сервис» → тип → характеристика → имя → «Добавить»**.
Тип удобнее искать по коду (`Switch`, `C_Option`, `BatteryService`), а не по русскому названию.
У «Параметра» (`C_Option`) все характеристики опциональные и по умолчанию выключены — включите
ровно одну: **Строка** для `status`, `error`, `rtk`, `ip`, `ssid`, `fw`, `mapstate`;
**Целое значение** для остальных.

> **Проверьте тумблер «Заряд battery» в «Рабочем столе».** Хаб создаёт сервис батареи выключенным
> на рабочем столе — плитки с зарядом не будет, пока не включите его руками. Остальные сервисы
> создаются включёнными, а лишнее сценарий уберёт сам.

**Основные:**

| Имя сервиса (пример) | Тип сервиса | Характеристика | Что делает |
|---|---|---|---|
| `Кошение mow` | Выключатель | Включен | включить — начать кошение, выключить — остановить |
| `На базу dock` | Выключатель | Включен | кнопка: отправить на базу (сама отжимается) |
| `Обновить состояние refresh` | Выключатель | Включен | кнопка: запросить свежие данные, не дожидаясь опроса |
| `Заряд battery` | Батарея | Уровень заряда, Состояние зарядки, Низкий заряд | заряд и признак зарядки |
| `Статус status` | Параметр | Строка | «Косит весь газон», «На зарядке», «Нет связи: …» |

**Настройки кошения:**

| Имя сервиса (пример) | Тип сервиса | Характеристика | Диапазон |
|---|---|---|---|
| `Высота кошения height` | Параметр | Целое | 30–70 мм |
| `Громкость volume` | Параметр | Целое | 0–100 |
| `Направление кошения dir` | Параметр | Целое | 0–180° |
| `Своё направление dirauto` | Выключатель | Включен | выкл — направление подбирает косилка |
| `Датчик дождя rain` | Выключатель | Включен | — |
| `Пауза после дождя, ч raintime` | Параметр | Целое | 0–8 часов |

**Кошение у базовой станции:**

| Имя сервиса (пример) | Тип сервиса | Характеристика | Диапазон |
|---|---|---|---|
| `Кошение у базы nest` | Выключатель | Включен | — |
| `Проходов у базы nestcount` | Параметр | Целое | 1–2 |
| `Высота у базы nestheight` | Параметр | Целое | 30–70 мм |
| `Визуальный контроль nestcheck` | Выключатель | Включен | — |
| `Уровень контроля nestlevel` | Параметр | Целое | 0 низкий, 1 средний, 2 высокий |

Обе высоты — газона и у базы — задаёт один и тот же нож, его ход **30–70 мм**. Значение вне
диапазона косилка отбрасывает вместе со всей командой (заодно теряя остальные поля `param_set`),
поэтому сценарий обрезает его сам и сразу показывает исправленное: введёте 120 — уедет 70,
и в хабе тут же встанет 70, не дожидаясь следующего опроса.

**Зоны.** Создайте столько кнопок, сколько у вас зон (до 16 каждого вида). Имена сценарий
подставит сам из разметки участка, лишние кнопки скроет — поэтому кнопка, которой не нашлось
зоны, с рабочего стола пропадает. Удалили зону в приложении Anthbot — соответствующая кнопка
исчезнет со следующим чтением разметки, добавили — вернётся. Разметка перечитывается раз в сутки
и сразу при перезапуске логики.

Зоны нумеруются **по возрастанию id**, а не по порядку в файле разметки: у Genie 800 он отражает
историю правок в приложении (100, 101, 102, 104, 103, 105), и без сортировки кнопка `zone4`
получала бы имя «Zone 5».

| Имя сервиса | Тип сервиса | Характеристика | Что делает |
|---|---|---|---|
| `Зона 1 zone1` … `Зона 16 zone16` | Выключатель | Включен | отметка ручной зоны для следующего кошения |
| `Авто-зона 1 azone1` … `Авто-зона 16 azone16` | Выключатель | Включен | отметка авто-зоны |

Кнопки зон — это **выбор, а не запуск**: они не гаснут и сами по себе ничего не отправляют.
Отметьте нужные зоны и включите «Кошение» — уйдёт одно задание со всеми отмеченными зонами.
Не отмечено ничего — косится весь газон. Так сделано потому, что косилка принимает список зон
только целиком: отправка на каждое нажатие затирала бы предыдущий выбор.

**Кнопки показывают и то, что косилка делает сама.** Опрос подсвечивает состав задания, которое
косилка выполняет сейчас, — в том числе запущенного из приложения Anthbot. Список переживает
завершение задания, поэтому на базе кнопки продолжают показывать последний набор: нажатие
«Кошение» повторит его.

Ваша отметка при этом главнее облака, и защищают её две вещи сразу.

Во-первых, кнопки переписываются, **только когда состав задания изменился**. Погасили зону —
опрос видит прежний состав, ничего нового не произошло, и кнопку не трогает. Перерисовка
случится, когда косилка возьмётся за другие зоны.

Во-вторых, как только вы нажали любую кнопку зоны, следующие **пять минут** опрос кнопки не
трогает вообще — даже если за это время косилка начала новое задание. Отсчёт начинается заново
с каждым нажатием, а «Кошение» снимает его сразу: выбор израсходован.

Порядок зон в списке косилка меняет от опроса к опросу, но новым заданием это не считается —
сравнивается набор, а не последовательность.

**Кнопки авто-зон не подсвечиваются.** Проверено на живой косилке: кошение авто-зоны состав
задания (`active_area`) не меняет вовсе — там остаётся прежний набор ручных зон. Авто-задание
видно по другим полям, но какая именно авто-зона косится, оттуда не следует. Поэтому кнопки
авто-зон остаются целиком вашими: сценарий их только переименовывает и прячет лишние.

Запуск авто-зоны из хаба при этом работает — подтверждено на Genie 800 сквозной проверкой:
нажатие кнопки увело косилку косить именно ту авто-зону, что была отмечена.

Зоны и авто-зоны за одно задание не смешиваются: если отмечено и то и другое, косятся зоны,
а про пропущенные авто-зоны сценарий пишет предупреждение в лог.

**Диагностика (только чтение):**

| Имя сервиса (пример) | Тип сервиса | Характеристика | Что показывает |
|---|---|---|---|
| `Ошибка error` | Параметр | Строка | «Нет ошибок» либо код ошибки |
| `RTK rtk` | Параметр | Строка | состояние спутниковой привязки |
| `IP-адрес ip` | Параметр | Строка | адрес косилки в сети |
| `Wi-Fi ssid` | Параметр | Строка | сеть, к которой подключена косилка |
| `Прошивка fw` | Параметр | Строка | версия системы косилки |
| `Состояние карты mapstate` | Параметр | Строка | `idle`, построение карты и т.п. |
| `Площадь карты maparea` | Параметр | Целое | м² |
| `Время сессии time` | Параметр | Целое | минуты текущего кошения |
| `Площадь сессии area` | Параметр | Целое | м² текущего кошения |
| `Наработка всего timetotal` | Параметр | Целое | минуты за всё время |
| `Площадь всего areatotal` | Параметр | Целое | м² за всё время |

Наработку и площадь **за всё время** Genie 800 не передаёт — эти два сервиса имеет смысл заводить
только на моделях M5/M9. Время сессии косилка отдаёт в секундах, в характеристику пишутся минуты.

**Время и площадь считаются за задание, а не за выезд.** Оба поля обнуляются с началом нового
задания и продолжают расти, пока оно идёт, — включая подзарядки посреди него. Проверено на живой
косилке 23.08.2026: у задания, шедшего через перерыв на зарядку, «Время сессии» показывало
147 минут при 34 минутах с момента выезда с базы, а с началом следующего задания оба поля
обнулились.

На прошивке 1.19.21 площадь не заполнялась вовсе (всегда 0), и раньше здесь стоял совет не
заводить сервис `area`. На 1.20.9 поле живое — 216 м² за то же задание, — так что сервис имеет
смысл.

### 3. Логический сценарий

Создайте логический сценарий с содержимым `build/AnthbotGenie.Logic.hub.js` (исходник —
[source/AnthbotGenie.Logic.js](source/AnthbotGenie.Logic.js)), затем в карточке виртуального аксессуара откройте **Логика** и подключите его. Заполните опции:

| Опция | По умолчанию | Описание |
|---|---|---|
| Логин Anthbot | — | как в мобильном приложении: телефон или e-mail |
| Пароль Anthbot | — | пароль от аккаунта |
| Код страны | `7` | телефонный код без плюса: 7 — Россия, 49 — Германия, 1 — США |
| Серийный номер косилки | пусто | нужен, только если косилок несколько; пусто — берётся первая |
| Период опроса, сек | 60 | чаще 30 секунд смысла обычно нет |
| Команды через shadow | выкл | запасной путь отправки команд, см. ниже |
| Отладка | выкл | подробный лог: каждый опрос, каждая команда и ответ облака |
| Значение в названии сервиса | вкл | «Статус На зарядке status» вместо «Статус status», см. ниже |

Логика привязывается к **одному** сервису — привязывайте к «Кошение mow». Изменения остальных
сервисов сценарий слушает сам, отдельно подключать их не нужно (и не нужно: у каждой привязки
свои опции и свой опрос).

Опрос начинается сразу после сохранения сценария. Через полминуты в сервисе `status` должно
появиться состояние косилки.

> **Сохранение кода не перезапускает уже привязанную логику.** Чтобы новая версия сценария начала
> работать, выключите и снова включите «Активно» в настройках привязки.

### 4. Что видно на рабочем столе

Хаб выводит на плитку рабочего стола значения выключателей и «измерительных» сервисов, а у сервиса
типа **Параметр** плитка остаётся пустой — значение видно только в карточке устройства. Поэтому
опция **«Значение в названии сервиса»** (включена по умолчанию) дописывает значение прямо в имя:
`Статус На зарядке status`, `Высота 70 мм height`, `Площадь карты 507 кв м maparea`. Ключ остаётся
последним словом, так что привязка сервисов не ломается.

Знаки препинания и надстрочные символы хаб из имени вырезает: `:` исчезает, `м²` превращается
в `м`, `кв.м` — в `квм`, `180°` — в `180`. Поэтому единицы записаны буквами (`град`, `кв м`),
а имена сравниваются без учёта таких символов — иначе имя никогда не совпало бы с ожидаемым и
сценарий переписывал бы его на каждом опросе.

> **Имя сервиса в хабе обрезается по 32 символам — вместе с ключом.** «Статус Возвращается на базу
> status» (34 символа) хаб сохранил как «Статус Возвращается на базу **stat**», ключ пропал,
> и сценарий перестал находить сервис — он застыл навсегда, до ручного переименования.
> Поэтому сценарий сам укладывает имя в предел: режет хвост значения, а ключ сохраняет.
> У статуса и ошибки подпись не пишется вовсе (`На зарядке status`, `Нет ошибок error`) —
> их значения сами по себе фразы, и подпись только съедала бы место.
>
> Если вы переименовываете сервисы вручную — держитесь того же правила: **ключ последним словом,
> имя не длиннее 32 символов**. Если ключ всё же потерялся, сценарий сервис не восстановит:
> верните имя руками через «Настройки → Переименование».
>
> Проверить все имена разом (и те, что ставит сценарий, и рекомендованные здесь):
>
> ```bash
> node tools/namecheck.mjs
> ```

**Редкое сценарий убирает со стола сам.** При первом опросе после запуска он выключает на рабочем
столе настройки «поставил и забыл» и диагностику: `refresh`, `volume`, `dirauto`, `rain`,
`raintime`, `nest`, `nestcount`, `nestheight`, `nestcheck`, `nestlevel`, `rtk`, `ip`, `ssid`,
`fw`, `mapstate`, `maparea`. В карточке устройства они остаются — просто не занимают место на столе.
На столе живут управление (`mow`, `dock`), состояние (`battery`, `status`, `error`), зоны,
наработка сессии (`time`, `area`) и `height` с `dir`.

Это делается **один раз**: вернёте плитку тумблером в «Рабочем столе» — сценарий её больше не
тронет. Умолчания применятся снова только при перезапуске логики (переключение «Активно»).

Скрытым сервисам сценарий возвращает чистое имя без значения — чтобы в карточке не застряло
значение, каким оно было в момент скрытия.

## 🧠 Как это работает

1. Логин на `api.anthbot.com` → токен доступа.
2. Список привязанных косилок, регион и адрес AWS IoT для выбранного серийника.
3. Временные ключи AWS под этот серийник (живут около часа, обновляются автоматически).
4. Опрос состояния: `GET /things/<серийник>/shadow?name=property` с подписью AWS SigV4.
5. Команды: публикация в топик `POST /topics/$aws/things/<серийник>/shadow/name/service/update`
   с телом `{"state":{"desired":{"cmd":…,"data":…}}}`.

Пятый шаг важен: документированный `UpdateThingShadow` (`POST /things/<sn>/shadow?name=service`)
облако принимает с кодом 200, но **косилка такие команды не выполняет** — проверено на живой
Genie 800: громкость не изменилась за 30 секунд, тогда как публикация в топик применилась за 5.
Прошивка слушает сам топик публикации, а не дельту shadow.

### Имена команд

Правило, выведенное из ответов Genie 800 и проверенное на живой косилке: **имя команды совпадает
с именем поля в `state.reported`**, а данные — это поля соответствующего подобъекта.

| Что меняем | Команда | Подтверждено на живой Genie 800 |
|---|---|---|
| высота кошения, направление, режим у базы | `param_set` | да (высота, `nest_switch`) |
| громкость | `volume_ctl` | да |
| настройки кошения у базы | `nest_param_set` | да (высота у базы, число проходов) |
| датчик дождя и пауза после дождя | `ctl_rainer` | да |
| старт кошения всего газона | `app_state` + `mow_start` | да |
| остановка задания | `stop_all_tasks` | да |
| возврат на базу | `charge_start` | да |
| кошение выбранных зон | `custom_area_mow_start` | да |
| кошение авто-зоны | `region_mow_start` | да |

**Все команды подтверждены на живой Genie 800** (прошивка 1.20.9, 24.08.2026) — таблица выше
закрыта целиком.

Команды движения проверены сквозняком: каждая нажималась в хабе, и результат сверялся с тем,
что вернула сама косилка — `globalmowing` с флагом `mow_full`, затем `idle` со сброшенными
флагами, затем `backtodock`. Кошение авто-зоны дополнительно сверено с картой в приложении:
робот косил именно отмеченную зону.

Настройки проверяются иначе — отправкой и сверкой с тем, что косилка вернёт следующим опросом
(`node tools/probe.mjs --check имя=значение`, исходное значение возвращается автоматически).
Дождь для проверки датчика дождя не нужен и ничего бы не доказал: `ctl_rainer` **настраивает**
датчик, а не сообщает о срабатывании. Признака «идёт дождь» косилка наружу не отдаёт вовсе —
в состоянии есть только `rain_switch` и `rain_continue_time`, то есть сама настройка.

Форма из HA-интеграции (`set_mow_params` с ключами `nest_*`) на Genie 800 принимается облаком,
но косилкой игнорируется — для моделей 600 / M5 / M9 может понадобиться вернуть именно её.

В песочнице сценариев Sprut.Hub нет ни криптографии, ни доступа к Java-классам, поэтому MD5,
SHA-256 и HMAC-SHA256 реализованы в глобальном сценарии на чистом ES5.

## 🩺 Если что-то не работает

**В статусе «Нет связи: …»** — текст после двоеточия говорит, на каком шаге всё встало.
`code=…` означает отказ облака Anthbot (чаще всего неверный логин, пароль или код страны).

**Команды не доходят до косилки, хотя состояние читается.** Если в логе видно, что облако
отвечает 200, а косилка не реагирует — для вашей модели может подходить второй путь доставки:
включите «Команды через shadow». На Genie 800 работает обратное — путь по умолчанию.

**Стабильный HTTP 403 при отправке команд** (состояние при этом читается). Путь топика едет в URL
закодированным (`%24aws%2F…`), и HTTP-клиент хаба мог нормализовать его по-своему — тогда подпись
не сходится. Сценарий сам перебирает три варианта подписи и запоминает рабочий, о чём пишет в лог
(`подпись пути топика: перешёл на вариант N`). Если не помог ни один — приложите лог.

**В логе «косилка не подтвердила настройку [X]».** Облако приняло команду, но следующим опросом
вернуло прежнее значение — для вашей модели формат этой команды отличается. Сравните в отладочном
логе, как выглядит настройка в ответе облака, и поправьте соответствующую `anthbotCommand…`
в глобальном сценарии. Сверка выполняется для всех настроек, кроме кошения, базы и зон:
их состояние меняется не мгновенно.

**Часть характеристик остаётся пустой.** У вашей модели эти поля называются иначе. Включите
«Отладку», найдите в логе строку `Состояние: {…}` — это сырой ответ облака — и сравните имена полей
с теми, что перечислены в `anthbotMapReported` в глобальном сценарии. Добавить путь в список
кандидатов — одна строка.

**В логе `Max call stack size exceeded (32)` раз в минуту, а карточка застыла.** Цепочка причин
в сообщении выглядит как `LOGIC[…] ← C[….Switch.On] ← LOGIC[…] ← …` на полтора десятка повторов.
Хаб обрывает цепочку причин на 32 звеньях, и опрос падает на первой же записи — статус ещё
успевает обновиться, всё остальное застывает. Ошибка версии 1.0: сценарий пересоздавал таймер
опроса из обработчика, поднятого его же записью, и новый таймер наследовал цепочку целиком —
та росла на два звена за опрос. Исправлено; обновите сценарий в хабе и **передёрните «Активно»** —
без перезапуска старый таймер со старой цепочкой продолжит крутиться.

**HTTP 403 от AWS при живом интернете.** Подпись проверяется по времени: если часы хаба ушли
больше чем на 5 минут, AWS отвергает любой запрос. Проверьте синхронизацию времени на хабе.

**Опрос идёт чаще, чем задано.** Такого быть не должно: сценарий снимает прежний таймер перед
постановкой нового. Если заметили — приложите лог, это ошибка.

**Изменили опции или код — ничего не поменялось.** Сохранение сценария не перезапускает уже
привязанную логику: опрос продолжает крутиться со старым кодом и старыми опциями. Чтобы изменения
применились, передёрните переключатель **«Активно»** в привязке логики (карточка устройства →
шестерёнка → Логика → «Anthbot Genie — газонокосилка»).

**Сразу после установки в логе `ReferenceError: "anthbot… is not defined`.** Не подключён
глобальный сценарий `AnthbotGenie.Global` — логический вызывает его функции через `global.*`
и без него не работает.

## 🧪 Тесты

```bash
cd ../SH_VirtualThermostat/Sprut.Hub_Tools/ScenarioSimulator && bun run cli run AnthbotGenie --root ../../../anthbot_genie_sprut
```

Крипто проверяется по опубликованным векторам (FIPS 180-4, RFC 1321, RFC 4231) и официальному
набору AWS `aws4_testsuite`, клиент облака — на моках HTTP, логика — на виртуальном аксессуаре
из `.tests/preset.json`.

Отдельно есть [tools/probe.mjs](../tools/probe.mjs) — он ходит в настоящее облако тем же кодом,
что и хаб. Учётные данные берёт только из переменных окружения.

```bash
node tools/probe.mjs                              # структура ответа и разбор состояния
node tools/probe.mjs --check nestcount=1          # проверить, применяется ли настройка (с автовозвратом)
node tools/probe.mjs --raw nest_param_set \
  --data '{"cutter_height":50,"mow_count":1,"pobctl_level":2,"pobctl_switch":1}' \
  --watch nestMowCount=1                          # проверить гипотезу о форме незнакомой команды
```

Проверка считается пройденной, только если изменилось состояние, которое вернула **сама косилка**:
код 200 от облака ещё ничего не значит — именно так и обнаружилось, что часть команд уходит в никуда.

## ⚖️ Ограничения

- Только облако: локального управления косилкой не существует.
- Зоны и авто-зоны создаются в приложении Anthbot; сценарий их только запускает.
- Настоящей «паузы» у косилки нет — остановка прекращает текущую задачу.
- Сценарий не создаёт устройства: набор сервисов задаётся руками один раз.
